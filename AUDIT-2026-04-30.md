## Findings — CLEAN with one gated capability

### No direct network code in `src/`

Searched for `reqwest|hyper|ureq|tokio::net|TcpStream|UnixStream|UdpSocket|std::net|http::Client|surf|isahc` — **zero matches** in any source file. URLs found were:

- Doc references (`example.test`, `example.com`)
- Test-fixture strings inside pattern detection unit tests
- Self-references (upstream repo URL in `--version` output and false-positive issue templates)
- Release-tag URLs constructed in `src/update.rs` but only consumed when the user runs `dcg update`

### `self_update` crate — opt-in only

`Cargo.toml` declares:

```toml
self_update = { version = "0.44", default-features = false,
  features = ["reqwest", "rustls", "archive-tar", "archive-zip", "compression-flate2"] }
```

This IS an HTTP-capable update mechanism. **However**, the call site is gated:

- `src/cli.rs:1947` — `Some(Command::Update(update)) => self_update(update)?;`
- `src/main.rs:235-284` — main entrypoint dispatches to `cli::run_command(cli)` only if `cli.command.is_some()`. Hook path (no subcommand, stdin-driven) **never** touches `self_update`.

Conclusion: the binary phones home **only** when the user explicitly runs `dcg update` / `dcg upgrade`. Acceptable; we will document this in fork README and never invoke the subcommand from automation. Future hardening option: feature-flag the `self_update` crate out of arkon-ai builds entirely.

### `self_heal_hook` — local-only file write

`src/main.rs:295-300` — if `config.general.self_heal_hook` is true, re-registers the DCG hook in `~/.claude/settings.json` if Claude Code overwrites it mid-session. **Local file write only**, no network. Configurable via `Config`.

### No telemetry / metrics emission

No matches for analytics SDKs, OpenTelemetry, Sentry, posthog, etc.
